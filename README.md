# Анализ вакансий — Категория 7

Веб-приложение для анализа вакансий с использованием методологии системного анализа.

**Вариант 6, Категория 7** — Управление, аналитика и сопровождение:
- System Analyst (Системный аналитик)
- IT Project Manager
- Product Manager (IT)
- Technical Writer (Технический писатель)

## Структура проекта

Репозиторий устроен так (этот README лежит в корне, рядом с папкой `vacancy_app`):

```
.
├── README.md                 # этот файл
├── Dockerfile
├── docker-compose.yml
├── .gitignore
├── .dockerignore
├── TSSAa_extracted/
│   └── TSSAa/
│       └── hh_raw_vacancies.jsonl   # исходные "сырые" данные (в git не хранятся, см. ниже)
└── vacancy_app/
    ├── app.py                # Flask-приложение, HTTP-маршруты
    ├── db.py                 # Работа с БД, загрузка данных, алгоритмы
    ├── requirements.txt
    ├── vacancies.db          # готовая SQLite БД (уже заполнена данными)
    ├── templates/
    │   └── index.html        # дашборд (4 блока)
    └── tests/
        └── test_app.py       # unit-тесты
```

> Важно: `db.py` ищет файл с исходными данными по пути
> `vacancy_app/../TSSAa_extracted/TSSAa/hh_raw_vacancies.jsonl`, то есть на уровень выше
> папки `vacancy_app`. Поэтому структура папок (как выше) должна сохраняться —
> не переносите `vacancy_app` в другое место без `TSSAa_extracted` рядом.

## Почему сырые данные не лежат в git

Файл `hh_raw_vacancies.jsonl` весит ~500 МБ — GitHub не пускает файлы больше 100 МБ
без Git LFS. Поэтому:

- папка `TSSAa_extracted/` добавлена в `.gitignore` и не попадёт в репозиторий;
- зато в репозиторий **включён** уже готовый `vacancy_app/vacancies.db` (~15 МБ) —
  он создаётся один раз функцией `load_data()` из `db.py` и дальше используется
  повторно, поэтому приложение работает сразу после клонирования репозитория,
  без необходимости иметь исходный jsonl-файл.

Если когда-нибудь понадобится пересобрать БД с нуля (например, обновились исходные
данные) — удалите `vacancy_app/vacancies.db` и положите свежий
`hh_raw_vacancies.jsonl` в `TSSAa_extracted/TSSAa/`: при следующем запуске
`app.py` база будет создана и заполнена автоматически (см. `init_app()` в `app.py`).

## Функциональность дашборда

### Блок 1 — Общие сведения о выборке
- Общее количество вакансий категории 7
- Разбивка по профессиям (круговая и столбчатая диаграммы)
- Число уникальных работодателей

### Блок 2 — Типовая вакансия
- Выбор профессии через выпадающий список
- Отображение одной реальной вакансии: название, работодатель, обязанности, требования, условия, навыки

### Блок 3 — Класс вакансий (обобщённая вакансия)
- Выбор профессии через выпадающий список
- Агрегированный портрет: топ требований, обязанностей, условий со всех вакансий
- Топ-15 наиболее востребованных технологических навыков

### Блок 4 — Поиск по навыкам
- Ввод навыков пользователя в текстовое поле, опционально диапазон зарплаты
- Поиск наиболее подходящих вакансий (TF-IDF + косинусное сходство)
- Отображение метрики схожести для каждой вакансии

## API-маршруты

| Метод | Путь                          | Описание                                  |
|-------|-------------------------------|--------------------------------------------|
| GET   | `/`                           | Главная страница (дашборд)                 |
| GET   | `/api/professions`            | Список профессий категории 7               |
| GET   | `/api/stats`                  | Общая статистика по выборке                |
| GET   | `/api/top_skills`             | Топ-20 навыков по всем вакансиям           |
| GET   | `/api/top_employers`          | Топ работодателей                          |
| GET   | `/api/typical/<profession>`   | Одна типовая (реальная) вакансия           |
| GET   | `/api/generalized/<profession>` | Обобщённый портрет вакансии              |
| POST  | `/api/search`                 | Поиск по навыкам (JSON: `skills`, опционально `salary_min`, `salary_max`) |

## Алгоритмы и технологии

- **Классификация вакансий**: правила по ключевым словам в названии (`classify_vacancy`)
- **Парсинг описаний**: BeautifulSoup (извлечение требований/условий из HTML hh.ru)
- **Извлечение зарплаты**: regex-эвристика по ключевым словам ("оклад", "зарплата" и т.п.)
- **Поиск по навыкам**: `TfidfVectorizer` + `cosine_similarity` (scikit-learn)
- **БД**: SQLite (таблицы `vacancies`, `requirements`)
- **Бэкенд**: Flask
- **Фронтенд**: HTML/CSS/JS, Chart.js

## Установка и запуск локально

Команды ниже выполняются **из корня репозитория** (там, где лежит этот README).

### Windows (Python launcher `py`)

```bash
# 1. Установить зависимости
py -m pip install -r vacancy_app\requirements.txt

# 2. Запустить приложение
py vacancy_app\app.py

# 3. Открыть в браузере
http://localhost:5000
```

### Linux / macOS

```bash
# 1. Установить зависимости
python3 -m pip install -r vacancy_app/requirements.txt

# 2. Запустить приложение
python3 vacancy_app/app.py

# 3. Открыть в браузере
http://localhost:5000
```

При первом запуске, если `vacancy_app/vacancies.db` пуст или отсутствует,
приложение автоматически прочитает `TSSAa_extracted/TSSAa/hh_raw_vacancies.jsonl`
и заполнит базу (см. раздел выше про сырые данные).

## Тесты

Тесты лежат в `vacancy_app/tests/test_app.py`. Запускать их также нужно
**из корня репозитория**:

```bash
# Windows
py -m pytest

# Linux / macOS
python3 -m pytest
```

С отчётом о покрытии:

```bash
py -m pytest --cov=vacancy_app --cov-report=term-missing
```

Тесты покрывают: классификацию вакансий, парсинг HTML, извлечение навыков и
зарплаты, CRUD-операции с БД, поиск по TF-IDF, все API-маршруты Flask. Тесты
используют временную БД (`tmp_path`) и не трогают реальный `vacancies.db`.

## Docker

В корне репозитория лежат `Dockerfile` и `docker-compose.yml`. Образ собирает
только содержимое `vacancy_app/` (включая уже готовый `vacancies.db`), поэтому
контейнер работает сразу, без необходимости подключать исходные данные.

### Сборка и запуск через Docker

```bash
# Сборка образа
docker build -t vacancy-app .

# Запуск контейнера
docker run -p 5000:5000 vacancy-app
```

Открыть в браузере: http://localhost:5000

### Через docker-compose (проще)

```bash
docker compose up --build
```

Остановить:

```bash
docker compose down
```

### Если нужно пересобрать БД из исходного jsonl внутри контейнера

`docker-compose.yml` дополнительно монтирует папку `TSSAa_extracted/` внутрь
контейнера в режиме "только чтение". Если вы удалили `vacancy_app/vacancies.db`
перед сборкой образа, при старте контейнера база будет собрана из
смонтированного `hh_raw_vacancies.jsonl` автоматически.

## Как залить проект на GitHub

Если у вас ещё нет git-репозитория в этой папке — выполните по порядку
(команды одинаковы для Windows/Linux/macOS, выполнять из корня проекта,
там же где лежит этот README, `Dockerfile` и т.д.):

```bash
# 1. Инициализировать репозиторий (если ещё не сделано)
git init

# 2. Добавить файлы (.gitignore уже исключит лишнее: __pycache__, .pytest_cache,
#    .coverage, и главное — папку TSSAa_extracted с большим jsonl-файлом)
git add .

# 3. Сделать первый коммит
git commit -m "Initial commit: vacancy analysis dashboard"

# 4. Создать пустой репозиторий на github.com (через сайт, без README/license —
#    они уже есть локально), скопировать его URL, например:
#    https://github.com/<ваш_логин>/<название_репозитория>.git

# 5. Привязать удалённый репозиторий
git remote add origin https://github.com/<ваш_логин>/<название_репозитория>.git

# 6. Назвать основную ветку main (если она называется master)
git branch -M main

# 7. Запушить
git push -u origin main
```

Если репозиторий на GitHub уже существует и просто нужно обновить код:

```bash
git add .
git commit -m "Update: README, Dockerfile, .gitignore"
git push
```

**Важно:** перед первым `git add .` убедитесь, что `.gitignore` лежит в корне
репозитория — иначе git попытается добавить 500-мегабайтный `hh_raw_vacancies.jsonl`,
и GitHub отклонит push. Если вы уже закоммитили этот файл раньше по ошибке,
его нужно убрать из истории git (например, через `git rm --cached <путь>` и новый
коммит), иначе он останется в истории репозитория даже после удаления.
